# Task: 15m market discovery helper

## Description

Add a `listUpDownMarkets()` helper to `src/mapping/gamma.ts` that returns active Polymarket BTC Up/Down 15m markets filtered by slug/tag and remaining-time-to-resolution. Will be called every 30 seconds by the oracle-lag scanner to refresh its active-market set.

## Acceptance Criteria

- [ ] New exported function `listUpDownMarkets(opts)` in `src/mapping/gamma.ts`
- [ ] Accepts options: `{asset: 'bitcoin' | 'ethereum' | ..., lifetime: '5m' | '15m', maxTimeToResolutionMin: number}`
- [ ] Returns an array of `UpDownMarket` objects (see shape below)
- [ ] Reuses the existing `/events?tag=crypto&order=startDate&ascending=false&active=true&closed=false` query plumbing from `listRecentCryptoEvents` (do not add a second fetch helper — factor out a shared `fetchRecentCryptoEventsRaw()` if needed)
- [ ] Filters client-side by:
  - market slug matches `^<asset-prefix>-updown-<lifetime>-\d+$` (e.g. `btc-updown-15m-1776005100`)
  - market tag list contains the uppercase lifetime tag (`'15M'` or `'5M'`)
  - `(endDate - now) ≤ maxTimeToResolutionMin * 60_000`
  - `(endDate - now) > 0` (not already resolved)
- [ ] `endDate` is used directly as the resolution time — do **not** parse titles
- [ ] Returns `[]` on fetch failure (don't throw) but logs the error structured
- [ ] Unit-testable (pure function given a canned Gamma response) — factor the filter out of the fetch if needed
- [ ] `npx tsc --noEmit` passes
- [ ] `npx eslint src/mapping/gamma.ts` passes

## Technical Details

### UpDownMarket shape
```ts
export interface UpDownMarket {
  marketId: string;         // Gamma market.id
  slug: string;             // e.g. 'btc-updown-15m-1776005100'
  question: string;         // market.question
  endDate: Date;            // parsed from market.endDate
  timeToResolutionMs: number; // endDate - now at fetch time
  lifetime: '5m' | '15m';
  asset: string;            // e.g. 'bitcoin'
  outcomePrices: [number, number];  // [UP, DOWN]
  clobTokenIds: [string, string];   // [UP_token, DOWN_token]
  yesTokenId: string;       // alias for clobTokenIds[0] — the UP token
  noTokenId: string;        // alias for clobTokenIds[1] — the DOWN token
}
```

### Filter logic
```ts
const slugRe = new RegExp(`^${slugPrefix}-updown-${lifetime}-\\d+$`);
const lifetimeTag = lifetime.toUpperCase(); // '15M'
const maxMs = maxTimeToResolutionMin * 60_000;
const now = Date.now();

for (const event of gammaEvents) {
  for (const m of event.markets || []) {
    if (!slugRe.test(m.slug)) continue;
    if (!event.tags?.some(t => t.slug === lifetimeTag)) continue;
    const endMs = new Date(m.endDate).getTime();
    const ttr = endMs - now;
    if (ttr <= 0 || ttr > maxMs) continue;
    // build UpDownMarket and push
  }
}
```

### Query params (reuse `listRecentCryptoEvents` style)
```
tag=crypto
order=startDate
ascending=false
active=true
closed=false
limit=50
```

50 is sufficient — active 5m and 15m markets across 7 assets produce ~14-28 events at any given time.

### Outcome prices and token IDs
- `market.outcomePrices` in Gamma is a JSON string like `'["0.505","0.495"]'` — use the existing `parseYesPrice` / `parseOutcomePrices` helpers already in `gamma.ts`
- `market.clobTokenIds` is a JSON string like `'["123...", "456..."]'` — use `parseClobTokenIds` from `gamma.ts`
- Order is always [UP, DOWN] for Up/Down markets (verify from one live market in the test)
