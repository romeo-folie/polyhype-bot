# Task: Worker wiring

## Description

Wire `ChainlinkFeed` + `OracleLagScanner` into `src/arb/worker.ts` alongside the existing `cryptoArbScanner`. Both run in the same `pga-arb` container. Add SIGTERM teardown.

## Technical Details

### Current `worker.ts` structure (read it first — don't assume)
Read `src/arb/worker.ts` fully before editing. It currently starts `cryptoArbScanner` and has its own lock pattern and SIGTERM handler. The oracle-lag feed + scanner additions layer on top without replacing anything.

### Wiring shape (illustrative)
```ts
import { ChainlinkFeed } from '../spot/feeds/chainlinkFeed.js';
import { OracleLagScanner } from './oracleLagScanner.js';

let feed: ChainlinkFeed | null = null;
let oracleScanner: OracleLagScanner | null = null;

async function main() {
  // ... existing lock acquisition, cryptoArbScanner startup ...
  
  feed = new ChainlinkFeed();
  await feed.start();
  oracleScanner = new OracleLagScanner();
  await oracleScanner.start(feed);
  
  logger.info('pga-arb worker started with oracle-lag scanner');
}

async function shutdown(signal: string) {
  logger.info(`received ${signal}, shutting down`);
  try {
    if (oracleScanner) await oracleScanner.stop();
    if (feed) await feed.stop();
    // ... existing cryptoArbScanner teardown, lock release, closeRedis() ...
  } catch (err) {
    logger.error('shutdown error', { err });
  }
  process.exit(0);
}

process.on('SIGTERM', () => void shutdown('SIGTERM'));
process.on('SIGINT', () => void shutdown('SIGINT'));
```

Match the **existing** worker's logger/error patterns — copy its style, don't introduce new conventions.

### Lock key uniqueness
The oracle-lag scanner has its own Redis lock (`lock:oracle-lag-scanner` from task 004). It does NOT share the `lock:arb-worker` (or whatever the current worker uses). Both locks exist in parallel. If the arb-worker lock can't be acquired, the whole worker should still exit (existing behavior). If the oracle-lag lock can't be acquired but the arb-worker lock can, the worker should still boot and run the crypto arb paths — just log a warning that oracle-lag is running elsewhere.
