## Description

Table-driven Vitest tests for the oracle-lag scanner's entry-rule evaluator — the pure function that takes a (market, move, config) tuple and returns `{shouldEnter, side, blockReason}`. No network, no Redis, no executor calls.

- [ ] Table-driven tests cover:

### Target pure function signature

export interface EntryEvaluation {
  shouldEnter: boolean;

### Block reason priority (define it)

1. no_move_data       (move is null)

This order matters for the test. Document it in a comment at the top of the evaluator.

### P(YES) invariant test
```ts
test('consensusProbability stored as P(YES) for DOWN entry', () => {
  const market = buildMarket({outcomePrices: [0.48, 0.52]}); // DOWN side cheaper
  const move = {pctMove: -0.08, oldPrice: 72800, newPrice: 72741.76, ticks: 5};
  const result = evaluateOracleLagEntry(market, move, defaultConfig);
  expect(result.shouldEnter).toBe(true);
  expect(result.side).toBe('DOWN');
  // P(YES) = 1 - P(DOWN) = 1 - (0.5 + 0.0008) = 0.4992
  expect(result.consensusProbability).toBeCloseTo(0.4992, 4);
});
```

This is the critical test — it guards against the Apr 11 UpDown bug where `consensusProbability` got stored as fair-value-of-our-side instead of P(YES).
