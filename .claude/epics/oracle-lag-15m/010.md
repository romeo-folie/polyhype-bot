# Task: Shadow review + flip decision

## Description

Analyze the 24-48h shadow log from task 009, spot-check ~20 would-fire events against actual Chainlink resolutions, compute the effective win rate, and make a go/no-go call on `ORACLE_LAG_ENABLED=true`.

## Acceptance Criteria

- [ ] Collect all `[oracle-lag] shadow candidate` events from the shadow window
- [ ] Compute and report:
  - [ ] Total shadow events
  - [ ] wouldTrade=true count (post-all-gates)
  - [ ] wouldTrade=true per hour (sanity check — expect several to tens per day)
  - [ ] Distribution (p25/p50/p75) of `movePct` at would-fire time
  - [ ] Distribution (p25/p50/p75) of `entryPrice` at would-fire time
  - [ ] Distribution (p25/p50/p75) of `timeLeftMin` at would-fire time
  - [ ] Breakdown of `blockReason` for the non-wouldTrade events
- [ ] For the **first 20 wouldTrade=true events**, spot-check the outcome:
  - [ ] Pull the market's `slug` and `endDate`
  - [ ] Fetch the Chainlink BTC/USD prices at window-start and window-end from the RTDS feed history OR Chainlink's public API (`https://data.chain.link/streams/btc-usd`)
  - [ ] Determine: would the entry have won or lost?
  - [ ] Compute shadow WR = wins / 20
- [ ] **Flip decision**:
  - [ ] If shadow WR ≥ 55% AND movePct distribution clusters ≥0.07 AND entryPrice distribution is inside [0.50, 0.62] AND no fatal log conditions → **flip go**
  - [ ] Otherwise → **flip no-go** (document why, propose next steps)
- [ ] Write the full analysis to `.claude/epics/oracle-lag-15m/updates/010/shadow-review.md` with all the numbers, the spot-check table, and the decision
- [ ] If flip go: add `ORACLE_LAG_ENABLED=true` and `ORACLE_LAG_MAX_TRADES_PER_HOUR=3` to `.env`, redeploy, confirm with the operator before handoff
- [ ] If flip no-go: leave `.env` alone, leave the feature in-tree, open a follow-up discussion with the operator

## Technical Details

### Log extraction
```bash
docker logs --since 48h polymarket-geopolitical-agent-pga-arb-1 2>&1 \
  | grep '\[oracle-lag\] shadow candidate' \
  | tee /tmp/oracle-lag-shadow.ndjson
```

Each line is a structured log with the `shadow candidate` fields. Parse with `jq` or a quick Python script.

### Computing percentiles
Quick Python in `.claude/epics/oracle-lag-15m/updates/010/`:
```python
import json, statistics
events = [json.loads(l.split('shadow candidate ')[1]) for l in open('/tmp/oracle-lag-shadow.ndjson')]
would = [e for e in events if e.get('wouldTrade')]
moves = sorted(e['movePct'] for e in would)
# ... p25/p50/p75 via statistics.quantiles(moves, n=4)
```

### Spot-check outcome resolution
For each of the first 20 wouldTrade events, we need the Chainlink BTC/USD price at two moments: the window start (= entry signal time) and the window end (= market resolution time). The 15m window for a market with slug `btc-updown-15m-{unix}` starts at `unix` and ends 15 minutes later.

Options for historical Chainlink prices:
1. **Our own RTDS recording**: if we capture the ChainlinkFeed ticks to disk during the shadow window, we have the ground truth. Consider enabling this in task 009 as a lightweight `chainlink-ticks.ndjson` dump. (If we didn't: use option 2.)
2. **Chainlink public data**: the `data.chain.link/streams/btc-usd` endpoint or on-chain aggregator round data on Polygon can give historical prices with high accuracy.
3. **Approximation via Polymarket's own resolution event**: the market will be marked closed and have an `umaResolutionStatus` on Gamma after the window ends — we can infer which side won by reading the final `outcomePrices`.

Option 3 is the simplest and fully self-contained — just re-query Gamma for each market after its endDate has passed and read the resolution.
