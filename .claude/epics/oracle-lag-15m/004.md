# Task: Oracle-lag scanner

## Description

New file `src/arb/oracleLagScanner.ts` — the main scanner loop that consumes the Chainlink feed, polls the 15m market discovery helper, evaluates entry rules per tick, and either shadow-logs candidates or fires entries via the existing `executor.ts` CLOB path.

## Acceptance Criteria

- [ ] `src/arb/oracleLagScanner.ts` exports a class/factory with:
  - [ ] `start(feed: ChainlinkFeed)` — begin the tick loop; takes a pre-started feed
  - [ ] `stop()` — clean shutdown for SIGTERM
- [ ] Tick loop runs on a `setInterval` with period ≤1000ms (not on every Chainlink message — that would be N×symbols/sec for the whole market list)
- [ ] Market discovery refresh every 30 seconds (store last-refresh timestamp, call `listUpDownMarkets({asset:'bitcoin', lifetime:'15m', maxTimeToResolutionMin:15})`)
- [ ] For each active BTC 15m market, on each tick:
  - [ ] Skip if `timeToResolutionMs / 60_000 < config.ORACLE_LAG_MIN_TIME_LEFT_MIN`
  - [ ] Compute `move = feed.getMoveSince('btc/usd', config.ORACLE_LAG_MOVE_WINDOW_SEC * 1000)`
  - [ ] Skip if `move === null` or `Math.abs(move.pctMove) < config.ORACLE_LAG_MIN_MOVE_PCT`
  - [ ] Determine entry side: `move.pctMove > 0 → UP` (YES), else `DOWN` (NO)
  - [ ] Skip if market price on entry side > `config.ORACLE_LAG_MAX_ENTRY_PRICE`
  - [ ] Check `updownThrottle.isLockedOut(marketId)` — skip if true
  - [ ] Check `updownThrottle.isHourlyCapReached()` — skip if true, using `config.ORACLE_LAG_MAX_TRADES_PER_HOUR`
  - [ ] Log `[oracle-lag] shadow candidate` structured event with ALL of: marketId, slug, movePct, entrySide, entryPrice, timeLeftMin, wouldTrade (bool = `ORACLE_LAG_ENABLED`)
  - [ ] If `config.ORACLE_LAG_ENABLED === true`: fire via `executor.executeSignal(...)` with a pre-sized stake (see Technical Details), log `[oracle-lag] entry` on success, call `updownThrottle.lockUpDownMarket(marketId, endDate)` + `updownThrottle.recordUpDownTrade(marketId, pnl=0 /* pending */)`
- [ ] Acquire/release a Redis lock (`lock:oracle-lag-scanner`) for single-instance safety, mirroring the existing `cryptoArbScanner` lock pattern
- [ ] SIGTERM handler releases the lock and calls `closeRedis()`, but does NOT have a `process.exit(0)` inside `redis.ts` (that's a known footgun — see CLAUDE.md)
- [ ] Per-symbol dedup: use the existing executor idempotency key pattern (`marketId + side + windowStartBucket`) so a rapid series of shadow candidates on the same market doesn't produce duplicate fires
- [ ] `npx tsc --noEmit` passes
- [ ] `npx eslint src/arb/oracleLagScanner.ts` passes

## Technical Details

### Signal construction (bypass Half-Kelly)
The plan says: `Edge is timing, not probability, so Half-Kelly doesn't apply. Fixed $5 stake.` Pass a pre-sized signal to the executor:

```ts
const signal: Signal = {
  marketId: market.marketId,
  side: entrySide, // 'UP' (YES) or 'DOWN' (NO)
  tokenId: entrySide === 'UP' ? market.yesTokenId : market.noTokenId,
  clobTokenIds: market.clobTokenIds,
  entryPrice: entryPrice, // market price on signal side
  stakeUsd: config.ORACLE_LAG_STAKE_USD, // <-- pre-sized
  orderType: 'FAK',
  source: 'oracle-lag',
  reason: `oracle_move_${movePct.toFixed(3)}pct_${windowSec}s`,
  category: 'crypto-regulatory',
  consensusProbability: entrySide === 'UP' ? 0.5 + movePct : 0.5 - movePct,
  // ^ stored-as-P(YES) invariant: see memory/feedback_consensus_pyes_invariant.md
  // for UP/YES side: fair = 0.5 + move/100; for DOWN/NO: P(YES) = 0.5 - move/100
  // This is a rough placeholder — the real edge isn't a probability, it's reprice lag
};
```

**⚠️ consensusProbability invariant**: this field is the monitor contract — it MUST be P(YES), never "fair-value-of-our-side". The previous BTC Up/Down fix (commit `c7f5ef8`) enforced this. Double-check on review.

### Executor call
```ts
const result = await executor.executeSignal(signal);
if (result.success) {
  logger.info('[oracle-lag] entry', {...});
  await updownThrottle.lockUpDownMarket(market.marketId, market.endDate);
  await updownThrottle.recordUpDownTrade(market.marketId, 0);
}
```

Use the `result.signal` for any post-execution logging — **NOT** the original `signal` variable. (Executor reassigns internally; this burned us before — see CLAUDE.md lessons learned.)

### Tick loop cadence
```ts
this.tickTimer = setInterval(() => {
  void this.onTick();
}, 1000); // 1Hz is sufficient — Chainlink publishes at ~1Hz anyway
```

### Redis lock pattern
```ts
import { acquireLock, releaseLock } from '../shared/redis.js';

const LOCK_KEY = 'lock:oracle-lag-scanner';
const LOCK_TTL_S = 60;

async start() {
  this.lockToken = await acquireLock(LOCK_KEY, LOCK_TTL_S);
  if (!this.lockToken) {
    logger.warn('[oracle-lag] another instance holds the lock, exiting');
    return;
  }
  // Refresh lock TTL periodically
  this.lockRefreshTimer = setInterval(() => {
    void refreshLock(LOCK_KEY, this.lockToken!, LOCK_TTL_S);
  }, 20_000);
  // ... start tick loop
}

async stop() {
  clearInterval(this.tickTimer);
  clearInterval(this.lockRefreshTimer);
  if (this.lockToken) await releaseLock(LOCK_KEY, this.lockToken);
}
```

Confirm the exact lock helper signatures by reading `src/shared/redis.ts` — the codebase has `acquireLock`/`refreshLock`/`releaseLock` but the argument shapes may differ.

### Shadow log shape (structured)
```ts
logger.info('[oracle-lag] shadow candidate', {
  marketId: market.marketId,
  slug: market.slug,
  movePct: +movePct.toFixed(4),
  entrySide,
  entryPrice: +entryPrice.toFixed(4),
  timeLeftMin: +(timeToResolutionMs / 60_000).toFixed(2),
  oldPrice: +oldPrice.toFixed(2),
  newPrice: +newPrice.toFixed(2),
  wouldTrade: config.ORACLE_LAG_ENABLED && !blocked,
  blockReason: blockReason || undefined,
});
```
