# Task: Chainlink feed unit tests

## Description

Vitest unit tests for `ChainlinkFeed` — message parsing, ringbuffer behavior, and `getMoveSince()` semantics. Does NOT test live WS connection (that's integration; keep it out of CI).

## Acceptance Criteria

- [ ] New file `src/spot/feeds/__tests__/chainlinkFeed.test.ts`
- [ ] Tests cover:
  - [ ] Parsing a valid Chainlink message yields correct `{symbol, value, oracleTs, receivedAt}`
  - [ ] Parsing a message from the parallel `crypto_prices` (Binance) topic is ignored (does NOT push into the buffer)
  - [ ] Parsing malformed JSON does not throw (logged and dropped)
  - [ ] Parsing a message with unknown symbol is ignored
  - [ ] Ringbuffer capacity: pushing 700 ticks leaves the latest 600 (or whatever capacity the feed uses)
  - [ ] `getMoveSince('btc/usd', 5000)`:
    - [ ] Returns `null` when buffer is empty
    - [ ] Returns `null` when only 1 tick exists
    - [ ] Returns `null` when all ticks are older than the window
    - [ ] Returns correct `{oldPrice, newPrice, pctMove, ticks}` for a normal case
    - [ ] `pctMove` sign is correct (up move → positive, down move → negative)
    - [ ] `pctMove` magnitude matches `(newPrice - oldPrice) / oldPrice * 100` to ≥4 decimal places
- [ ] No network calls — mock the WebSocket entirely OR use a dependency-injected message-push method
- [ ] `npx vitest run src/spot/feeds/__tests__/chainlinkFeed.test.ts` passes
- [ ] Uses `vitest`'s fake timers where needed (`vi.useFakeTimers()` / `vi.advanceTimersByTime(...)`) to control `Date.now()` for window tests

## Technical Details

### Injecting messages without a real WS
The cleanest pattern: expose a test-only `_pushRawMessage(raw: string)` method on the feed, or make the message parser a pure function `parseChainlinkMessage(raw: string): Tick | null` that's independently exported and testable.

Prefer the pure parser — it's the cleanest boundary:
```ts
// in chainlinkFeed.ts
export function parseChainlinkMessage(raw: string | Buffer): ChainlinkTick | null {
  // ...
}
```

Then tests import `parseChainlinkMessage` directly.

Ringbuffer and getMoveSince can be tested by instantiating the feed with `start()` mocked out, then calling an internal push method (either exposed for tests with a `__test_pushTick` or similar, or accessible because the class exposes it as a method).
